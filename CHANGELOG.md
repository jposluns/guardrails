# Changelog: AIQT Guardrails™

The user-facing changes for each public release.

## 1.0.5: The chat-assistant skill (2026-09-18)

- AIQT 1.0.5 ships the chat assistant: the AIQT governance core packaged for a chat assistant, as a Skill you upload to Claude or a portable instruction file for other assistants (ChatGPT, Copilot, Gemini). It guides the assistant toward the AIQT standard: claims matched to their sources, checks kept at full strength, and "finished" verified before it is said. The evidence page shows what has been tested on each platform.
- Includes the portable AIQT governance core and a curated security-rule subset for chat use.

## Unreleased (toward 1.1.1)

- AGENTS.md now places the rules listed in .aiqt/core/must-deliver.toml directly after the apex rule, ahead of every other rule, so growth in an unlisted rule can no longer push a listed rule out of the first 32768 bytes. This change alone left AGENTS.md byte-identical (the listed rules already came first; the next item changes its bytes), and GEMINI.md and the Copilot instructions keep AIQT priority order. tools/gen_agents.py now stops with exit 2, writing nothing, when that list is absent, malformed or names a rule that is not in the corpus, and the adopter conformance suite judges AGENTS.md in the same order and, like the generator, reports an installed AGENTS.md with no such list as MALFORMED (exit 2). Release classification, recorded here and not computed by any gate (tools/check_release_delta.py runs in genesis mode on this tree and computes no delta): this renderer change has, on its own, no output byte change (byte-only); the new tools/_must_deliver.py is an added pack path; and the conformance change is an exit change in a tool outside every renderer declaration.
- The rule that a fix is verified in its commit (vfxcmt) leaves .aiqt/core/must-deliver.toml, with a recorded removal, so every listed rule, the commit-identity rule included, now ends at least 6600 bytes inside the first 32768 bytes of AGENTS.md instead of 26. That rule is still delivered whole, now as the first rule after the listed ones, but it is no longer guaranteed: 48 bytes of growth ahead of its end, in the AGENTS.md header, the blocks before the rules, the rules ahead of it or its own text, push it past the cap, and the must-deliver gate only reports that. The AGENTS.md header now states the order (the apex, the listed rules, then the rest), so AGENTS.md bytes change (the header and that rule's place), and the agents renderer's semantics revision is now 3, which tools/gen_renderers.py now holds as the agents floor, so the bump cannot be reverted on its own. Release classification: the order changes, and the same rules as before lie whole inside the first 32768 bytes (byte-only).
- The must-deliver margin is now enforced, not only reported: .aiqt/core/must-deliver.toml moves to format-version 2 with reserve-bytes = 512, and tools/check_must_deliver.py fails (exit 1) when any listed rule ends fewer than 512 bytes inside the first 32768 bytes of AGENTS.md; a margin of exactly 512 passes. The reserve protects listed rules only, never an unlisted one. A reserve that is not an integer of at least 0, is missing, or exceeds warn-margin-bytes, and a working list in any format-version but 2, fail closed (exit 2). The list at the comparison base is read by a base parser that accepts exactly format-version 1 or exactly format-version 2, so the list ratchet still compares against a base written before this change. The list ratchet also fails (exit 1) when reserve-bytes is lower than the reserve-bytes listed at the comparison base (a format-version 1 base counts as 0), so a lowered reserve fails the gate. The adopter conformance suite reads an installed list still in format-version 1 for its AGENTS.md order and names it an older version with the migration step (set format-version = 2 and add reserve-bytes), instead of reporting it as MALFORMED. AGENTS.md keeps its bytes. Release classification, recorded here and not computed by any gate: a code change to tools/_must_deliver.py, which is in the agents, adapters, claude and skill renderer closures, with no output byte change (byte-only); the gate and conformance changes are exit changes in tools outside every renderer declaration.
